## Что считается агентом

В доступных локальных Codex `session_meta` до начала этой ретроспективы найдено 110 `source.subagent.thread_spawn` записей с parent/thread/agent_path, 49 root-session records и 92 guardian records при фильтре cwd по пути проекта. Это **251 файловых записей ограниченной выборки**, а не полный штат, число уникальных работников, законченных задач или показатель эффективности. Cwd в иных Temp worktrees может не попасть в выборку. Private transcripts и содержимое datasets в публикацию не включены.

Имена путей подтверждают существование отдельных threads для Standards, Spec, Ponytail, exploration/design, discovery, Graphify research, ground truth и A/B navigation. Связь конкретного результата с ролью дополнительно требует отчёта. Guardian — инфраструктурная категория metadata; её продуктивность и назначение здесь **UNKNOWN**. Отдельные implementation, merger, TDD, browser и acceptance AI-workers для всех задач **не установлены**. Наличие раздела «independent review» само по себе не подтверждает spawn.

Ниже **девять аналитических групп ролей**, а не девять уникальных historical agents. Orchestrator и implementation в первой строке объединены как функции процесса: отдельное разделение по исполнителям неизвестно. Локальные источники и границы воспроизводимости перечислены в [evidence index](evidence-index.md).

## Skills, программы и проверки

**Skill — инструкция, не агент.** TDD задаёт цикл RED→GREEN; браузер/CDP/Edge — программные инструменты; pytest/Node — test runners; GitHub Actions — CI; integration acceptance — работа/артефакт. Ни один из них не является независимым AI reviewer без thread evidence. [NPI-09 report](../../npi09_implementation_report.md) честно отличает automated headed Edge от human acceptance и закрепляет уже одобренные seams.

27 имён skill-файлов встречаются в исторически отправленных командах чтения metadata-filtered sessions: `codebase-design`, `code-review`, `computer-use`, `control-chrome`, `control-in-app-browser`, `diagnosing-bugs`, `domain-modeling`, `graphify`, `grilling`, `grill-with-docs`, `implement`, `improve-codebase-architecture`, `openai-docs`, `plugin-management`, `ponytail`, `ponytail-audit`, `ponytail-review`, `pr`, `research`, `retro`, `setup-matt-pocock-skills`, `skill-installer`, `tdd`, `ticket`, `to-spec`, `to-tickets`, `writing-for-agents`. **Это подтверждение отправленных read attempts, не 27 успешно применённых workflows.** Некоторые файлы/версии могли отсутствовать; Graphify body читался в audit. По отдельным named workflows фактическое применение подтверждается report evidence; полную численность успешных исторических skills установить нельзя.

Физически сейчас найдено **103 SKILL.md** в global skills и plugin cache, включая `.system`. Это installation/cache inventory, не перечень enabled providers и не historical use. Catalog имён/описаний составлен из frontmatter, без чтения нерелевантных тел, приватных settings и credentials. Текущие process instructions проверены: code-review/TDD/Ponytail/PR/research, implementation/decomposition/handoff/retro и architecture/domain workflows. Их конкретные изменения предложены в [workflow v2](workflow-v2.md) и [backlog](improvement-backlog.md); внешние skills не модифицированы.
